# 图像生成与修订

把用户的视觉意图整理成准确、可检查的图片产物。只使用运行时提供的 `GenerateImage`；不要自行调用图片供应商 API、CLI、脚本或不存在的图像工具。

## 1. 真实工具契约

`GenerateImage` 统一承担文生图和单图修订：

```text
GenerateImage({
  prompt,
  output_path,
  input_image_path?,
  aspect_ratio?
})
```

- 没有 `input_image_path`：根据文字生成新图。
- 有 `input_image_path`：以这一张 Workspace 图片作为编辑或派生来源。
- 每次调用只支持一张输入图。不要在提示词中假装工具同时看到了其他图片；需要多个角度时，以已确认主图为锚点，分别派生并保存每个视角。
- 输入只能是当前 Agent 已获授权的 Workspace 路径，不能传远程 URL、系统路径或其他项目文件。
- 输出必须写入 `output/spatial/images/`，使用稳定、可辨认且不覆盖无关资产的文件名。
- 可选画幅只有 `1:1`、`3:2`、`2:3`、`4:3`、`3:4`、`16:9`、`9:16`。编辑时若保持原构图更重要，可以省略。
- 不选择供应商或模型，不设计运行时 fallback；工具负责持久 receipt、发布与恢复。

`GenerateImage` 是外部调用，但对调用它的单个 Agent 是同步工具。多个独立资产适合由多个 Agent 并行生成；不要把同一个资产中存在依赖关系的主图和派生视角并行成互相矛盾的设计。

## 2. 何时使用

适合：

- 新概念图、空间氛围图、物体或环境模块参考图；
- 从已确认主图派生侧视、后视、材质或光照版本；
- 只改变现有图片中的指定元素，同时尽量保持其余内容；
- 用户明确要求图片，或视觉锁定会实质改善后续 World/Lux 结果。

不适合：

- 可直接通过 SVG、HTML/CSS、Canvas 或已有源文件确定性完成的简单图形；
- 直接生成 GLB、PLY、SPZ 或修改 Scene 变换；
- 仅为了展示工具而增加用户没有需要的候选；
- 用一张图片声称已经验证三维几何、背面结构、真实尺度或物理正确性。

## 3. 判断生成还是编辑

- 用户要改变现有图片并保留其中大部分内容：使用单图修订，明确写出“只改变什么”和“必须保持什么”。
- 图片只用于描述风格、构图、对象或空间意图：在当前工具限制下，它仍是唯一输入锚点；提示词要说清楚是延续设计还是修改原图。
- 没有输入图：生成新图。
- 用户要求多个不同资产：为每个资产建立独立提示词和输出路径，不把不同对象塞进一个模糊的批量提示。

## 4. 工作方法

1. 确认图片的实际用途、主体、必要内容和禁止变化项；信息已经足够时直接执行，不为了普通美术判断反复提问。
2. 若有输入图，明确它是编辑目标、设计锚点还是视角派生来源。当前工具只有一个输入槽。
3. 把请求整理为简洁的视觉规格。用户已经写得具体时只规范结构，不擅自增加人物、道具、品牌、文案或故事。
4. 根据用途选择画幅。空间环境和 World 参考通常使用 `16:9` 或 `3:2`；独立物体参考通常使用 `1:1` 或 `4:3`，但用户已有构图优先。
5. 调用 `GenerateImage`，等待当前图片真实返回。
6. 检查实际产物，而不是只检查工具成功状态：主体、轮廓、视角、构图、材质、光照、文字和所有不变量是否符合要求。
7. 需要修改时一次只做一个有目标的变化，并在每轮重新写明关键不变量；保存为新的清晰路径，除非用户明确要求覆盖。
8. 把最终 Workspace 路径和图片在后续 World、Lux 或 Scene 中的用途说清楚。

详细提示词原则见 `/skills/imagegen/references/prompting.md`。需要可直接改写的空间、物体和编辑示例时读取 `/skills/imagegen/references/sample-prompts.md`。

## 5. 提示词骨架

按实际需要选择字段，不要求机械填满：

```text
Use case: <用途类别>
Asset type: <图片将用于哪里>
Primary request: <核心视觉请求>
Input image: <编辑目标 / 设计锚点 / 视角派生来源>（可选）
Scene/backdrop: <环境>
Subject: <主体>
Style/medium: <照片 / 概念图 / 产品渲染等>
Composition/framing: <机位、景别、主体位置>
Lighting/mood: <光照与氛围>
Color palette: <颜色>
Materials/textures: <材质细节>
Text (verbatim): "<必须准确出现的文字>"
Constraints: <必须保持、必须满足>
Avoid: <不得出现>
```

提示词不是封闭 schema。只保留能改变结果的内容，避免把完整模板本身变成噪声。

## 6. 空间创作专用边界

- World 参考图：清楚描述空间类型、入口、主要开口、中央可用区域、光照和氛围；不要只写抽象风格词。
- Lux 独立物体：主体完整可见，轮廓清晰，遮挡少，背景简洁，避免透视夸张和无关道具。
- Lux 环境模块：主图要交代模块边界、地面连接关系、正面和核心结构；背面会被看见时再派生一致的后视或侧视。
- 多视角不是同时自由重画。先确认一张 canonical 主图，再以该图作为 `input_image_path` 分别派生每个方向；重复设计身份、比例、部件、材质和颜色不变量。生成后逐张检查一致性，再交给 `CreateObject3D`。
- 概念图是设计约束和视觉证据，不是几何证明。看不到的结构标记为 `unknown`，不得在审阅中凭想象宣布正确。

## 7. 恢复与诚实交付

- 工具错误若表示外部结果不确定，不要创建新调用原样重提；先依赖 durable receipt 恢复或把风险交给 Root/用户处理。
- 工具返回图片不等于图片符合要求。只有查看真实产物后才能使用 `verified` 描述可见内容。
- 不声称文字、透明度、身份、透视或多视角一致性已经保持，除非当前图片能够直接确认。
- 用户可见说明默认使用简体中文；工具名、路径和必要的视觉术语保持准确原文。
