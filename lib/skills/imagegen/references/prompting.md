# 图片提示词原则

这份参考只讨论如何把意图写成更可靠的 `GenerateImage` 提示词。工具参数、Workspace 权限和恢复规则以 `imagegen` Skill 为准。

## 结构与具体程度

- 推荐顺序：环境或背景 → 主体 → 关键细节 → 构图与机位 → 材质和光照 → 必须保持与避免内容 → 图片用途。
- 复杂请求用短标签组织，不要把所有要求塞进一个长段落。
- 用户提示已经具体时，只整理和消歧，不增加新的创意要求。
- 用户只给出泛化方向时，可以补充真正改善结果的构图、景别、材质或使用场景，但不要擅自增加角色、道具、品牌、口号或剧情。

## 构图和相机

- 明确广角、正常透视、特写、正交感、俯视或三分之四视角等真正相关的机位语言。
- 需要留给 UI 或文字的位置时才要求负空间。
- 不要无依据决定“放在左边/右边”；空间关系应来自用户要求或已有画面。
- 为 3D 参考生成图片时优先完整轮廓、较低遮挡和正常焦段，避免鱼眼、极端广角、景深遮蔽和裁断关键结构。

## 编辑与不变量

- 修订提示要同时写出变化和不变量：`只改变 X；保持 Y、Z 不变`。
- 每次迭代重新声明关键不变量，不能假设模型自动记住上一轮。
- 视角派生需要保持设计身份、比例、部件数量、材质、颜色和时代风格，只改变相机方位及其自然可见面。
- 一轮只做一个主要变化。若同时改造主体、机位、风格和光照，很难判断失败来自哪里。

## 输入图角色

当前 `GenerateImage` 每次只有一张输入图：

- `编辑目标`：保留原图大部分内容，只修改指定部分。
- `设计锚点`：延续主体、风格、材质或空间语言，可重新构图。
- `视角派生来源`：保持同一设计，从指定新方向重画。

不要在提示词中引用不存在的 Image 2、Image 3。需要多个视角时分别调用并给出独立输出路径。

## 文字

- 必须出现的文字使用引号，要求逐字呈现且不增加其他文案。
- 说明字体风格、大小、颜色和位置，但不要承诺生图模型一定能正确拼写。
- 文字正确性重要时必须查看成图；错误就做单点文字修订或改用确定性的排版工具。

## 空间与物体参考

### World 或环境图

- 写出空间用途、入口、主要开口、核心区域、可行走/可摆放中央区域和远景关系。
- 光照要说明来源、方向、时间和氛围，避免只写“电影感”。
- 若 World 只承担氛围背景，明确中央区域干净、平整、开阔，避免生成无法编辑的密集主体。

### Lux 物体或模块

- 主体完整可见、清晰落地、轮廓明确；尽量使用干净中性背景。
- 说明真实需要的几何部件和连接关系，避免只写审美标签。
- 建筑、道路、地台等模块要能看出边界、接缝和主要结构。
- 后视或侧视图必须重复主图中的部件、比例、材质和颜色，不得自由重新设计。

## 实际检查

工具成功只证明图片被生成。逐项检查：

- 主体是否正确、完整且没有多余部件；
- 视角和构图是否符合用途；
- 支撑方向、承载面和重力关系是否合理；
- 材质、颜色和光照是否一致；
- 编辑要求的所有不变量是否保持；
- 文字是否准确；
- 多视角之间是否真的是同一设计。

单张遮挡图无法证明背面或三维结构。无法从图中确认的内容标记为 `unknown`。

## 常用用途类别

- `photorealistic-natural`：自然摄影、真实纹理和正常光照。
- `product-mockup`：清晰产品轮廓、材质和受控背景。
- `stylized-concept`：空间、建筑、道具和游戏环境概念设计。
- `ui-mockup`：真实产品界面或低保真线框，而非概念艺术。
- `infographic-diagram`：结构化布局、明确标签和箭头。
- `precise-object-edit`：只替换或移动指定元素。
- `lighting-weather`：只改变光照、天气和气氛。
- `style-transfer`：保持指定内容，迁移视觉语言。
- `sketch-to-render`：保持布局、比例和透视，把草图转成渲染图。
