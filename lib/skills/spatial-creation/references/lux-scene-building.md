# Lux 模块化场景创作指南

## Lux 在 Scene 中的角色

`CreateObject3D` 不只用于小型道具，也可以生成可复用的环境模块。根据后续编辑粒度选择资产边界：

- 环境模块：地台、道路段、庭院、建筑外壳、店铺单元、桥梁或一块完整景观。模块内部通常一起移动和复用，作为一个 GLB 实例加入 Scene。
- 独立物件：树、灯、标牌、家具、车辆、装饰品或需要单独选择、移动、删除和复用的建筑部件。每件可独立登记，重复实例可共享一份模型。主体明显且不易参数化时用生成件，常规小件可用源码实现。场景内的树冠、地被和小件分工见 [混合搭建参考](hybrid-scene-assembly.md)。
- 全景环境：只承担远景、天空、整体光色和包围式空间氛围。需要局部编辑的建筑、道路、地表结构和道具不要烘焙进全景或 World。

同一摆放关系、同一生命周期且很少单独调整的内容可以合成一个模块；需要独立变换、复用、替换或语义修改的内容应拆成多个资产。不要把整座城市或完整地图无差别合成一个无法编辑的单体，也不要把每一块砖拆成独立资产。

已发布 GLB 提供资产几何和材质，Three.js 源码定义场景布局，并可直接提供程序化网格、曲面、CSG、材质和动画。PLY 仅作为可选的高质量视觉替身，不参与选择、碰撞或场景结构判断。

## 从概念美术建立实施清单

以整体概念图和补充机位为共同视觉基准。对照原照片与口述辨别必须保留的内容，再从概念图列出实现清单，按后续编辑方式决定资产边界。

- 环境清单：天空、天气、远山、遥远天际线、整体光色和包围式远景；有可见天空或远景的新建室外场景默认另行生成近中景低信息的 `scene_environment_panorama`，提示词要求左右连续、地平线稳定的 2:1 等距柱状全景。Agent 查看真实图片后决定是否定向修订，再把全景加入 assets.json，通过源码加载并设置 scene.background；通常不要直接复用包含全部建筑的概念图。
- 基础环境模块：连续地台、坡面、道路段、庭院板块、水岸、桥面、群山近景或大块地表。有辨识度的地貌可用 Lux GLB。规则地台、路面和台阶可直接用源码制作。将实际承载物登记为 role:'terrain'，用真实网格检查摆放。
- 建筑模块：建筑主体、附属塔楼、连廊、入口构筑物、围墙等。体量大或需要单独调整的部分分开生成；同一摆放关系且不会独立调整的部分可以合并。
- 独立物件：树木、灯具、家具、标牌、车辆、装饰和交互装置，按选择、移动、复用和删除需求拆分。

实施清单应记录每项资产的用途、预期观察方向、与其他资产的连接关系和需要保持的视觉特征。它服务于 Agent 的制作与委派，不要求用户管理文件名、Job 或 Scene revision。

多图还原时，给独立资产选一张最清楚的原照或已确认的概念图。有辨识度的开口、桥栏、门窗和支撑优先按原照，派生的屋背和组合位置按布局假设。生成概念把透孔砖栏简化成平板桥时，制作桥的单件参考图应回到原照，而不是沿用简化结果。

近景有明显高差或材质特征时，先划出整段可通行面、台地、挡墙、沟床和坡脚。沿沟街巷按入口、前坪、坡台等场地段划分，每段尽量保留一整条地形横断面。用一张地形母图固定总体边线与高差，先生成连续带纹理网格。需要分块时，沿真实路向切分同一份网格，保留共同原点、纹理坐标和对齐参数。重组时对所有地形块使用同一高程比例，逐块归一化会破坏接缝。实际验证包括切口顶点对应、主路在接缝两侧的表面命中、坡度，以及建筑和桥梁落点的高程。必须分开生成时，先定义共用剖面，检查端面的宽度、走向和高度，再确认是否需要过渡段。地面小件适合用作局部补充。

## 生成单件参考图和 GLB

1. 先为每个待生成的资产制作一张 canonical 主视图。用场景概念图或清楚的原始物件照片作 `GenerateImage.input_image_path`，提示词说明资产在画面中的位置与身份，要求单一主体、主体完整、无遮挡、背景干净。写清需要保留的比例、材质、开口、底部和支撑。移除其他物件、人物、地景与投影干扰。
2. 判断主图是否已说明需要的几何。院门建筑从两侧都能看到、背墙开口参与动线，或支撑和厚度对落地很重要时，在第一次生成前补相应视角。以主图为 `input_image_path`，每次派生一个侧视、后视或斜后视。检查设计身份、关键轮廓、比例、材质、部件数量与开口位置一致。被推测的侧面仍需标记为推测。简单道具通常一张就足够。
3. `CreateObject3D` 的 `reference_image_paths` 传 1–4 张独立图片，主图在先，补充图按观察顺序排列。多图生成以图片为几何输入，`prompt` 不会传给多图生成端。把结构和材质要求落实在各张参考图里。使用当前 Workspace 的授权图片，避免提交整场概念图、拼图或互相矛盾的视角。`output_path_prefix` 填该物件的输出目录，如 `output/spatial/objects/courtyard-gate`。
4. 资产发布后检查真实 manifest 与 GLB，重点看开口是否贯通、厚度、朝上方向、支撑面和失真。有缺陷再修订该件图片或补视角后重建。多视角可减少遮挡导致的歧义，实际几何仍需复核，无法证明 CAD 精度、真实尺寸或不可见内部结构。

例如还原老院子时，整体图用来确认院门、主屋和树的相对位置。单件图分别生成主屋、门楼和有辨识度的石桌，门楼补一张从院内朝外的参考以说明通道。铺地、门槛、常规石凳和细小边饰可用源码实现。要保留特殊石雕时可以复用经过检查的 GLB。

## 组装与复核

1. `CreateSpatialScene` 创建源码工程。读取已发布资产的 manifest，从真实产物确认 GLB 路径，加入 `assets.json`。以 `ctx.assets.loadGLB` 加载并按稳定 key 登记。在候选构建的隔离视图检查单件完整性，再在全景里核对相对布局。用 Write/Edit 修改组合、布置、补充几何、光照与机位。源码协议见 [scene-code.md](scene-code.md)。
2. `RunSceneCode` 生成候选构建，先检查真实模块，再从顶视、入口人眼视角和远景复核场景。顶视负责动线与占地，入口机位用来判断人眼尺度，远景负责轮廓与天际线。只在需要观察某个问题时追加视图。坐标基与 GLB/PLY 对照见 [spatial-orientation-review.md](spatial-orientation-review.md)。
3. 在起伏地形上用 `ctx.geometry.placeOn` 或 `QuerySceneGeometry` 向下命中真实网格，核对支撑与间距。桥梁分别量两端桥面、两岸承台和沟底，连同主路到桥头的过渡一起检查。瓦顶门测两根柱脚和门洞内多处净空。建筑以多个底部测点找平，可按场地需要补局部石基或台阶。未命中或缺少查询几何时说明无法验证。布局问题优先改源码参数，确认为 GLB 缺陷时才处理生成资产。
4. 室外场景用源码加载授权全景。全景和可选 Aholo World 3DGS 不阻塞主 Scene。以工程图、真实网格查询和约束检查验证用户要求，最后 `PublishSceneBuild` 发布。观察由无头服务执行。

## 异步并行创作

Lux 生成可能持续数分钟。`CreateObject3D` 返回 `prepared` 和 `job_id` 后，后台 Worker 会继续提交、轮询、镜像和发布；当前 Agent 不应停下来等待。

进入制作且视觉基准明确后再并行生产。早期概念探索先完成用户确认。

- 同一资产：参考图完成并检查后提交 Lux，随后继续设计下一资产。
- 多个独立资产：Root 可按依赖和团队容量委派多个 Asset Maker。产品不设置固定的图片或 3D 数量上限；后台 Worker 的可配置并发只控制本机瞬时处理吞吐，后续任务会留在持久队列中，不应因“槽满”要求 Agent 重试。
- 任务完成：系统把 `spatial_job_update` 作为新的持久后台事件通知 Root，不会给原 `tool_use_id` 再补一个结果。
- Root 若正处于 `waiting_user`，这些事件会持久排队并在用户回答后统一消费；不覆盖已经发出的 `AskUserQuestion`。
- 资产组装：Root 将 `published` 资产交给唯一 Scene Assembler 串行放置；不要让多个 Agent 同时修改 current revision。
- 状态异常：`failed` 可以选择替代设计；`unknown` 可能已经产生外部付费副作用，必须停止自动重提。

不要把 `GetSpatialJob`/`WaitSpatialJob` 当作常规等待手段。只有用户主动追问状态或需要诊断恢复时才读取 Job；普通创作依赖完成通知继续。
