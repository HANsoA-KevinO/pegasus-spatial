# Lux 模块化场景创作指南

## Lux 在 Scene 中的角色

`CreateObject3D` 不只用于小型道具，也可以生成可复用的环境模块。根据后续编辑粒度选择资产边界：

- 环境模块：地台、道路段、庭院、建筑外壳、店铺单元、桥梁或一块完整景观。模块内部通常一起移动和复用，作为一个 GLB 实例加入 Scene。
- 独立物件：树、灯、标牌、家具、车辆、装饰品或需要单独选择、移动、删除和复用的建筑部件。每个物件单独生成并加入 Scene。
- 全景环境：只承担远景、天空、整体光色和包围式空间氛围。需要局部编辑的建筑、道路、地表结构和道具不要烘焙进全景或 World。

同一摆放关系、同一生命周期且很少单独调整的内容可以合成一个模块；需要独立变换、复用、替换或语义修改的内容应拆成多个资产。不要把整座城市或完整地图无差别合成一个无法编辑的单体，也不要把每一块砖拆成独立资产。

GLB 是 Scene 选择、变换和结构判断的真值。PLY 仅作为可选的高质量视觉替身，不参与选择、碰撞或场景结构判断。

## 从概念美术建立实施清单

用户确认的是最终场景体验，不是一个不可拆分的单体模型。开始 3D 制作前，从概念美术和文字约束中列出真正需要实现的内容，并按后续编辑方式决定资产边界：

- 环境清单：天空、天气、远山、遥远天际线、整体光色和包围式远景；默认另行生成近中景低信息的 `scene_environment_panorama`，提示词要求左右连续、地平线稳定的 2:1 等距柱状全景。Agent 查看真实图片后决定是否定向修订，再用 `SetSceneEnvironment` 直接设为环境；通常不要直接复用包含全部建筑的概念图。
- 基础环境模块：连续地台、坡面、道路段、庭院板块、水岸、桥面、群山近景或大块地表。只要用户未来可能整体移动或替换，就作为 Lux GLB，并用 `AddSceneTerrain` 标记为可查询地表。
- 建筑模块：建筑主体、附属塔楼、连廊、入口构筑物、围墙等。体量大或需要单独调整的部分分开生成；同一摆放关系且不会独立调整的部分可以合并。
- 独立物件：树木、灯具、家具、标牌、车辆、装饰和交互装置，按选择、移动、复用和删除需求拆分。

实施清单应记录每项资产的用途、预期观察方向、与其他资产的连接关系和需要保持的视觉特征。它服务于 Agent 的制作与委派，不要求用户管理文件名、Job 或 Scene revision。

## 单图优先，按证据升级

每个资产默认只准备一张 canonical 主视图并直接生成：只表现当前建筑或模块，主体完整、无遮挡、透视清楚、背景干净，不把周围建筑和景观一起画入。避免裁切、人物遮挡、强景深和会被误认为几何的复杂背景。单图是正常生产路径，不因资产体量大就自动增加图片。

资产发布后查看真实 GLB。只有背面、厚度、支撑、入口或明显不对称结构已产生不可接受的可见错误，或者用户明确要求更高的多向一致性时，才以原主图为 `input_image_path` 派生侧视、后视或斜后视并重新生成。补充图必须保持主体比例、材质、部件数量、开口位置和关键轮廓一致；互相矛盾的视图不能提交。多视角只是有成本的纠错升级，不能证明 CAD 精度、真实尺寸或不可见内部结构。

所有输入必须是当前 Workspace 中已授权、可读取的图片，不能传任意远程 URL。

## 组装与复核

不要求执行固定步骤。根据目标自由组合：先做概念图、直接生成模块、补独立物件、建立 Scene、摆放、截图复核，或从已有资产继续修改。

推荐的判断顺序是：

1. 从已确认概念美术建立 World、环境模块、建筑和独立物件的实施清单，确认哪些内容应一起移动，哪些内容必须独立编辑。
2. 先在一份干净 Scene JSON 中规划地台、主建筑体量、门环、道路/广场、桥梁和关键高差。布局使用稳定语义 `key`、绝对变换和目标尺寸表达；不要依赖 Viewer SDK 中不存在的代理体构造器，也不要为了占位而阻塞真实资产制作。
3. Lux 资产发布后，从顶视、入口人眼视角和远景三个机位检查真实模块。顶视负责动线与占地，入口机位负责人尺度和视觉压迫，远景负责轮廓与天际线。未通过时优先修改 Scene JSON 中的位置、旋转和尺寸，不用生成资产补救布局。
4. 单独新生成并检查近中景低信息的 2:1 等距柱状全景；同时为每个 Lux 模块生成一张足以识别几何的 canonical 主图。复杂建筑拆成基座、塔身、门环、连桥、冠部等可控模块。概念美术、环境全景、Lux 单资产参考图三类图片不要混用；补充视角只在真实 GLB 暴露问题后按需生成。
5. 每个 Lux 资产发布后先读取 manifest、bounds 并在独立预览中检查完整性、朝上方向、支撑面和明显失真。不合格资产不进入 Scene；合格资产按稳定 `key` 逐件放入或替换。每增加一个关键模块就截图复核，而不是一次塞入多个未验证模型。
6. 查看环境全景并按需定向修订，再用 `SetSceneEnvironment` 建立远景背景。Aholo World 3DGS 只作为可选的定点体积背景试验，不阻塞主 Scene。
7. 复杂搭建继续使用 `output/spatial/scenes/<scene-id>/scene.json` 作为声明式源文件：填写当前 `expected_scene_version`、稳定节点 `key`、来源 Job、角色、绝对位置/旋转和目标 `fit` 尺寸，再用 `ApplySceneSpec` 一次原子应用完整期望状态。只在简单一次性修补时使用逐物体 Scene 工具。
8. 在起伏 Lux 地形上摆放前，用 `QuerySceneSurface` 获取目标水平坐标对应的真实 GLB 命中点；用返回点作为绝对位置，避免包围盒顶面、全景视觉或概念图造成悬空/穿地。
9. 局部问题优先 `Edit` Scene JSON 中的节点参数后再次 `ApplySceneSpec`；真实模块的关系逐件确认后，最后统一处理光照、材质曝光、阴影与地面融合。只有天空、远景、整体光色或包围氛围需要变化时才替换全景环境。

坐标基、落地姿态与 GLB/PLY 对照遵循 `spatial-orientation-review.md`，不能用 Scene rotation 掩盖资产格式或本地坐标基错误。

## 异步并行创作

Lux 生成可能持续数分钟。`CreateObject3D` 返回 `prepared` 和 `job_id` 后，后台 Worker 会继续提交、轮询、镜像和发布；当前 Agent 不应停下来等待。

这里的并行生产以概念方向已经由用户确认为前提。早期点子阶段先共同完善方向和概念图，不要为了“提高并行度”提前创建成员或生产一批尚未确认的 3D 资产。

- 同一资产：参考图完成并检查后提交 Lux，随后继续设计下一资产。
- 多个独立资产：Root 按资产拆分和团队可用 Agent 同时委派多个 Asset Maker。产品不设置固定的图片或 3D 数量上限；后台 Worker 的可配置并发只控制本机瞬时处理吞吐，后续任务会留在持久队列中，不应因“槽满”要求 Agent 重试。
- 任务完成：系统把 `spatial_job_update` 作为新的持久后台事件通知 Root，不会给原 `tool_use_id` 再补一个结果。
- Root 若正处于 `waiting_user`，这些事件会持久排队并在用户回答后统一消费；不覆盖已经发出的 `AskUserQuestion`。
- 资产组装：Root 将 `published` 资产交给唯一 Scene Assembler 串行放置；不要让多个 Agent 同时修改 current revision。
- 状态异常：`failed` 可以选择替代设计；`unknown` 可能已经产生外部付费副作用，必须停止自动重提。

不要把 `GetSpatialJob`/`WaitSpatialJob` 当作常规等待手段。只有用户主动追问状态或需要诊断恢复时才读取 Job；普通创作依赖完成通知继续。
