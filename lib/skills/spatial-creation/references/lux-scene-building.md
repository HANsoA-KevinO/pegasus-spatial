# Lux 模块化场景创作指南

## Lux 在 Scene 中的角色

`CreateObject3D` 不只用于小型道具，也可以生成可复用的环境模块。根据后续编辑粒度选择资产边界：

- 环境模块：地台、道路段、庭院、建筑外壳、店铺单元、桥梁或一块完整景观。模块内部通常一起移动和复用，作为一个 GLB 实例加入 Scene。
- 独立物件：树、灯、标牌、家具、车辆、装饰品或需要单独选择、移动、删除和复用的建筑部件。每个物件单独生成并加入 Scene。
- World：只承担远景、天空、整体光色和包围式空间氛围。需要局部编辑的建筑、道路、地表结构和道具不要烘焙进 World。

同一摆放关系、同一生命周期且很少单独调整的内容可以合成一个模块；需要独立变换、复用、替换或语义修改的内容应拆成多个资产。不要把整座城市或完整地图无差别合成一个无法编辑的单体，也不要把每一块砖拆成独立资产。

GLB 是 Scene 选择、变换和结构判断的真值。PLY 仅作为可选的高质量视觉替身，不参与选择、碰撞或场景结构判断。

## 选择单视角还是多视角

简单、近似对称、背面不重要或仅用于低风险装饰的资产，可以用一张清晰主视图生成。

以下资产优先使用 2–4 张一致参考图：

- 大型环境模块、建筑或道路单元；
- 正反面差异明显、轮廓不对称或存在遮挡的物体；
- 会从多个方向观察的核心资产；
- 单张图无法确定背面、侧面、厚度或支撑关系的设计。

先用 `GenerateImage` 得到并确认主视图。需要补充视角时，以已确认主视图作为 `input_image_path`，分别生成后视、侧视或斜后视参考。所有视图必须表现同一个设计，保持主体比例、材质、部件数量、开口位置和关键轮廓一致；使用干净背景、完整构图并避免裁切。提交前先比较视图，发现结构冲突就修订参考图，不把互相矛盾的图片交给 3D 生成。

调用约束：

- 单张参考图：可同时提供 `prompt` 和一个 `reference_image_paths` 路径。
- 多张参考图：把 2–4 个 Workspace 路径放入 `reference_image_paths`，省略 `prompt`，让一致视图共同定义几何。
- 所有输入必须是当前 Workspace 中已授权、可读取的图片，不能传任意远程 URL。

多视角只能减少遮挡和背面歧义，不能证明 CAD 精度、真实尺寸或不可见内部结构。结果仍需用真实 GLB 渲染和补充观察验证。

## 组装与复核

不要求执行固定步骤。根据目标自由组合：先做概念图、直接生成模块、补独立物件、建立 Scene、摆放、截图复核，或从已有资产继续修改。

推荐的判断顺序是：

1. 确认哪些内容应一起移动，哪些内容必须独立编辑。
2. 为重要模块选择足以约束几何的参考视角。
3. 使用 `CreateObject3D` 生成 GLB，并在发布后读取 manifest 与 bounds。
4. 使用 `AddSceneObject` 加入 Scene；修改前用 `InspectSpatialScene` 获取绝对变换。
5. 使用 Agent 相机从入口、主要动线和侧后方截图，检查尺度关系、遮挡、支撑方向与构图。
6. 局部问题优先移动、替换或新增 Lux 资产；只有远景和整体氛围需要变化时才替换 World。

坐标基、落地姿态与 GLB/PLY 对照遵循 `spatial-orientation-review.md`，不能用 Scene rotation 掩盖资产格式或本地坐标基错误。

## 异步并行创作

Lux 生成可能持续数分钟。`CreateObject3D` 返回 `prepared` 和 `job_id` 后，后台 Worker 会继续提交、轮询、镜像和发布；当前 Agent 不应停下来等待。

- 同一资产：参考图完成并检查后提交 Lux，随后继续设计下一资产。
- 多个独立资产：Root 按资产拆分和团队可用 Agent 同时委派多个 Asset Maker。产品不设置固定的图片或 3D 数量上限；后台 Worker 的可配置并发只控制本机瞬时处理吞吐，后续任务会留在持久队列中，不应因“槽满”要求 Agent 重试。
- 任务完成：系统把 `spatial_job_update` 作为新的持久后台事件通知 Root，不会给原 `tool_use_id` 再补一个结果。
- 资产组装：Root 将 `published` 资产交给唯一 Scene Assembler 串行放置；不要让多个 Agent 同时修改 current revision。
- 状态异常：`failed` 可以选择替代设计；`unknown` 可能已经产生外部付费副作用，必须停止自动重提。

不要把 `GetSpatialJob`/`WaitSpatialJob` 当作常规等待手段。只有用户主动追问状态或需要诊断恢复时才读取 Job；普通创作依赖完成通知继续。
