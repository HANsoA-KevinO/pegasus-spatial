# 生成资产与 Three.js 混合搭建

用于已确认设计的场景还原、植被填充和局部反馈。选材看轮廓、视差、承载、近看距离、独立编辑需求和重复次数。

## 1. 按用途选表示

| 需要保留的东西 | 起手做法 | 转换条件 |
| --- | --- | --- |
| 老屋轮廓、风化砖木、桥体、树冠、不规则近景地形 | 复用已检查的 GLB，缺件时用单件图生成 Lux3D | 形体基本正确时用代码调位置、比例和接口。主体结构或材质失真时，修订参考图后定向生成 |
| 石桌凳、陶罐、长凳、木箱、招牌、门槛、踏步和铺地 | 用 Three.js 做可控几何，尺寸、字样、位置和材质写入源码或 JSON | 纪念物、特有雕刻或近看轮廓辨识度高时，选实物图或生成 GLB |
| 大量蕨丛、灌木和垂藤 | 共用透明图集，按地形用薄片批量布置 | 需要贴近绕看、独立交互或可靠体积时，换局部 GLB 或明确的查询几何 |
| 天空、远山和远处林线 | 独立的 2:1 等距柱状全景 | 枝干需要近处视差、遮挡或选中时，作为场景中的真实对象 |

同一对象可混用表示。桥体可用生成 GLB，栏外多余桥板可以裁切，桥台开口和两岸铺地由几何接续。重复道具共用原型。判断场景里缺少的是地标、整片绿量、连续路面还是生活痕迹，再补相应层。乔木、林下地被与远景各自有作用，按视角分配密度和预算。

## 2. 图集到地被

1. **出图。** 先选能解释环境的几种植物。一张 2×2 图集可放深绿蕨丛、阔叶灌木、垂藤和较浅的新叶蕨。每格一个完整轮廓，四周和格间留白。地被保留根部方向，垂藤保留上挂点和向下的枝叶。保持光照、季节、清晰度相近。用真实透明底，或纯品红等与叶色明显分离的平色底。看清叶间缝隙、细枝、格子位置和边缘后再用。图集按纹理处理。提示词见 `/skills/imagegen/references/sample-prompts.md`。
2. **取透明度。** 实际文件有有效 alpha 时直接复用。平色底用确定性抠色，按背景色分离强度做渐变 alpha，给半透明边缘去掉底色溢色。检查背景透明、主体保留和细叶未被大片误抠。项目已有可保存衍生纹理的能力时，将原图和 alpha 版分开存放并记录来源。也可以把原图声明为 `kind: texture`，在场景创建时用 `ctx.assets.loadTexture` 和 `ctx.createCanvas` 处理像素，再构造 `CanvasTexture`。结合载入图片的方向核对 `flipY` 和四个格子的 UV，防止上下对调。衍生纹理应能由冻结的项目资产与源码重建。
3. **做薄片。** 每格的 UV 范围向内留边，防止缩小采样时串到隔壁。蕨和灌木可用两到三张交叉、略倾斜的薄片，根部锚点低于叶冠。垂藤按上挂点和局部墙向定位，检查下缘是否悬在墙外。共享图集和材质，优先用 `alphaTest` 保留叶缘和镂空，按实际像素调阈值，减少半透明排序问题。按类别或可选中的植被片区使用 `InstancedMesh`，设定矩阵后更新实例缓冲和包围范围。需要单株编辑的树或地标植物单独登记。
4. **按场地成片。** 在真实地形上定义沟岸、坡脚、墙缝和树下种植区。用固定种子的簇状采样与最小间距，变化密度、尺度、朝向和少量色调。地被向下射线命中实际承载面，树对准真实根颈，垂藤查墙面接点。留出主路、台阶、门洞、桥头、建筑足迹与重要视线。地形、桥或房屋变化后，更新相邻的排除区和落点。薄片的 CPU 射线可能命中透明区域，验证通行时按用途选择实体对象或提供合适的查询几何。
5. **查看实际效果。** 用入口图检查遮荫和空旷，用俯视检查覆盖和动线，用近景检查品红边、穿地、悬浮、重复朝向和薄片感。摄像机陷进树冠时先换到邻近可读机位，必要时重新落树。记录图集、实例数量和覆盖区域。碰撞与通行只按已执行的测量范围报告。

乔木可共用一份有完整树干、根部和树冠的 GLB。量原模型根颈相对原点的偏移，结合实例旋转和缩放换算落点。用不同尺度、朝向与分组打破重复。检查树冠是否遮住标志、入口或镜头。复用网格与材质，观察面数、显存和绘制开销。高质量 PLY 按需加载，避免为整片重复林木逐株复制高斯预览。

## 3. 连续地形、铺地和小件

- 沿整段路、沟、挡墙和台地先做连续母图及 GLB，需拆分时从同一份网格切块。保留共同原点、坐标基、UV 和高程比例。用实际切口顶点和两侧地表命中验证接缝。局部开口修改后，复核外边界及分段接缝，保留原件和新版本的来源。
- 规则小件优先用少量原型。陶罐可用 `LatheGeometry` 做带内壁的回转轮廓，并将轴转到 Z-up。石桌凳参数化台面、底座和高度。长凳和木箱做出支腿、板厚和接缝。招牌以确认过的字样和顺序做 `CanvasTexture`，在实际构建检查字体回退、翻转、比例与挂点。文字证据不足时保留为未知或有说明的补全。
- 给小件分配用途和位置，例如石桌凳布在前坪边，陶罐靠墙脚，木箱在粮店开间外侧。按支撑脚或接触面测落点。连片石板可登记为铺地区段，频繁选改的小件用独立稳定 key。
- 随坡铺石先冻结实际地形，在路中心线和局部宽度内取样。每块取中心和边缘，地表变化大时增采样或缩小石块。变化石块宽窄、拼缝与边角，用石色、风化和苔痕过渡。用近景检查穿地、悬空、重面闪烁和规则方格的贴片感。大块共面底层可能遮住石块，先修重叠和取样，再调颜色。补台阶前量门槛并检查原模型自带的台阶。

## 4. 桥头、门洞和截图反馈

1. **分开定位问题。** 对用户截图，先锁定实际 revision、对象和视角，用相近机位看前后。桥自身看砖栏位置、实际桥面、端部和梁底。地基看两岸座位、沟缘、门前标高，以及旧压顶或路沿是否横挡。外观看宽度突变、浅色台座、短坡跨在旧栏上、颜色跳变和拼贴感。
2. **先测真实几何，再改接口。** 桥的长轴和正面有时相对 GLB 原轴倾斜，从真实形状识别后再变换。量两个桥端和两岸承载面，按沟缘确定有效跨度。沿路到桥测中心线，再补横向样线核对净宽，查梁底和沟底净空。旧压顶挡路时，在实际地基网格上开口或局部找坡。铺地沿通道展开到两岸，接住桥面和下一个入口。接坡压在挡墙上可能通过单点高差检查，画面仍会留下明显拼贴。
3. **保留生成件中可用的部分。** 砖栏落在桥中线时，补短端或俯看参考来约束单侧栏与完整桥面。多图生成仍可能给错位置。若多余桥板可单独裁切，保留主体并封切面，重建法线与 UV 或给切面独立石材，检查近景拉伸、漏口和砖纹跳变。门洞被生成成封门时，可裁出贯通开口，保留屋顶和双柱，补洞内收边。用射线或截面验证空腔和支撑。主体不可用时再换生成件，补图返回 `unknown` 时遵守付费任务恢复规则。
4. **证据配对。** 交付相近视角的前后图、俯视和必要的侧视或截面。记录两端高差、坡度、桥面可用宽度、采样位置和未覆盖部分。量测与视觉都通过才说该问题已解决。数值采用场景相对单位，射线抽样只支持对应区间的几何判断。完成真实角色控制和碰撞验收后，才报告人物可以通过。

## 5. 构建、发布和排错

- 选用产物进入用户当前的真实 Workspace。把 GLB、纹理和参数写进 `assets.json` 及场景源码，保留原始生成件、衍生版本和验证图的血缘。确认 `loaded`、`instances_in_scene`、稳定 key 和实际图像。用同一 Scene 的新 revision 提供可打开、可选中的结果。核对场景与构建 ID，确保用户打开的是已发布版本。
- 裁过的桥或门、重排过的地基和新加的接坡以发布构建里的实际网格为准。原 PLY 只匹配原 GLB 的视觉形态。衍生件切换高质量时保留当前 GLB，或用与衍生件配套的 PLY，防止旧桥板或封门回来。
- 区分供应商生成、文件下载物化、Scene 构建和发布。供应商任务完成但 GLB/PLY 仍在物化时，可先做独立的程序细节，资产进入 `published` 后再导入。本地预览成功但正式构建报体积超限时，核对冻结资产、预览专用 PLY 是否被错误打进构建包，以及实际运行的 Worker 版本。定位执行链后再对同一候选复核，保留当前可用 revision。
